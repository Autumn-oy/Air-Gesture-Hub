# 云枢 · Air Gesture Hub

**前置摄像头识别"四指并拢、手心朝镜头、整体扫动"，把它变成屏幕上的一次滑动。**
不需要 root，也不需要前台服务，也无需后台上锁保活 —— 它就是一个**无障碍服务**。

核心取舍只有一句话：**相机只在"你真正要用"的时候才活着**。
手贴近“接近光传感器”唤醒，相机只在勾选的应用里、且只在贴近后的 **8 秒窗口**内开启；
离开那个应用约 1 秒断开，息屏一律关闭。空闲时它几乎不占 CPU。

安装只有两步：
1. 授予**相机**权限；
2. 去系统设置里打开本应用的**无障碍服务** —— 这就是它的工作方式。

> ⚠️ **保活必读（华为 / 荣耀尤其重要）**：到「设置 → 应用和服务 → 应用启动管理」把它设为
> **手动管理**并允许**后台活动**（其它安卓机同理，入口名称可能不同）。否则系统的"一键清理"会对它 force-stop —— 那不仅杀进程，
> **还会把无障碍服务一起关掉**（表现就是"清一下就彻底不能用了"，需要重新打开无障碍）。

## 🖐 怎么用

```
手贴近接近光传感器（约 5cm，一般在摄像头位置）      →  服务唤醒，相机连上
        ↓
把手后退到离摄像头 10~20cm，四指并拢、手心朝镜头、停稳  →  屏幕出现「请滑动」
        ↓
竖屏：上下左右扫一下（横屏：只扫上下）                →  屏幕上滑动一次
        ↓
冷静期 1000ms（防连触）；想再来一次不用重新贴近，8 秒窗口内继续即可
```

- 竖屏下支持**上下左右四个正方向**；**横屏下只支持上下**（左右扫不响应，提示语也会变成「请上下滑动」）；斜着扫一律不判定。
- 横屏的方向补偿是**按屏幕旋转实时推导**的，不是写死的常量：横屏有两种朝向（屏幕转 90° / 270°），
  它们需要的补偿量**相差 180°**，所以"一个横屏常量"必然让其中一边上下颠倒。
  推导与依据（含 MediaPipe 侧的三处源码证据）写在
  `app/src/main/java/com/airgesture/sweep/ScreenOrientation.kt` 顶部。
- 窗口内**每次检测到手都会续期**，连续做手势不会被切断。
- **桌面（启动器）固定不接管** —— 刻意的：桌面上的滑动没有意义，而且会跟桌面动画抢资源。

## ⚙️ 实现方式

| 层 | 用什么 |
|---|---|
| 宿主 | **无障碍服务**（`AccessibilityService`）—— 没有前台服务、没有常驻 Activity |
| 取流 | **CameraX**，前置、**640×480**、`KEEP_ONLY_LATEST`（只处理最新帧，避免延迟滚雪球） |
| 推理 | **MediaPipe HandLandmarker**（`hand_landmarker.task` 随包分发），arm64-v8a 单 ABI |
| 判定 | 四指并拢 + 手心朝镜头 + 整体位移 → One Euro 滤波 → 状态机（IDLE → SETTLE → WATCH → COOLDOWN） |
| 注入 | `dispatchGesture` 合成一次滑动（早期那套 `ACTION_SCROLL` 已废弃） |

判定逻辑**先在 Python 里实现并测边界，再由它导出跨语言测试向量**，Kotlin 侧回放同一批输入比对：

```
probe/detector_ref.py  →  probe/make_sweep_vectors.py  →  SweepVectors.kt（31 个向量）
        └─ 29 个 Python 单测钉住边界（慢漂移 / 斜扫 / 并拢度 / 冷静期…）
```

这样"参数改了、但两端行为不一致"这种事不会悄悄发生。

## 🔋 相机什么时候开（省电的核心）

| 条件 | 相机 |
|---|---|
| 没贴近传感器（接近光窗口未开） | **关** |
| 前台 App 不在白名单里 | **关** |
| 息屏 | **关** |
| 桌面（启动器） | **关**（即使被勾进白名单也不开） |
| 白名单内 + 窗口内 + 亮屏 | **开** |
| 离开白名单 App | **约 1 秒内断开**（真机实测 0.79 / 1.25 / 1.64 秒） |
| 窗口过期（8 秒没检测到手） | **关**，下次必须重新贴近 |

三条降载手段砍的是**不同的**开销，缺一不可：

| 手段 | 砍什么 | 实测效果 |
|---|---|---|
| **跳帧**（每 4 帧推理 1 次） | "算"：推理 + 它带来的 GC | 推理线程 21%→**7.4%**，GC 21%→**7%** |
| **相机作用域（白名单）** | "取流"：CameraX + 相机 HAL | 桌面 / 非白名单 CPU → **0.0~0.5%** |
| **接近光触发（8 秒窗口）** | 让相机只在真正要用时活着 | 占空比接近零 |

**白名单是唯一模式**，界面上没有"全局模式"这个挡位。
名单里**永远含云枢自己**（灰阶、不可撤销），所以"一个都不勾"就等于**任何 App 里都不生效**——
与直觉一致（引擎里"空名单 = 全部放行"那条兜底因此永远够不着，它是给"刚装还没勾选"留的保险）。

## 📊 实测数字（华为 P40 Pro / Android 12，拔线测）

**功耗**

| 指标 | 实测 |
|---|---|
| 空闲 CPU（桌面 / 息屏） | 97% → **0.0~2%**（单核） |
| 应用内取流时 | **43~50%** 单核（跳帧后）—— 但相机占空比只有 4.84% |
| 相机使用强度（2026-09-25，7h20m 日常工况） | **66 次 / 共 21 分 15 秒**，占空比 **4.84%**，会话中位 20 秒 |
| 整机同窗口 | **13.6 %/h**（屏亮 76% 的重度使用）；本 App **账面 0.32%** |
| 整机隔夜息屏 8h45m（荣耀机实测） | 本 App **0.742 mAh**，整机 624 mAh → 约占 **0.12%** |

> ⚠️ **关于那个 0.32%**：这台华为的 `batterystats` **不统计相机功耗**（power profile 里没有
> camera 项），CPU 项的归因也是坏的 —— 所以"相机开着"的那 21 分钟与推理 CPU **并没有进账本**。
> 按物理估算，本 App 的真实占比可能是 **1~2.6%**。全部原始测量数据保留在开发记录里
> （`docs/` 目录，**不随仓库发布**），需要时向作者索取。

**内存**（空闲态，相机已解绑）

| 指标 | 实测 |
|---|---|
| PSS / RSS | ≈ **150 MB / 240 MB** |
| `GL mtrack` | **42.9 MB** —— 解绑相机后**依然占着**；它是 MediaPipe 的 GL 上下文，与相机是否绑定无关 |
| Java 堆 | 6~11 MB（也就是"我们自己写的代码"那部分） |

结论：**内存的主体在推理栈（MediaPipe 的 GL 上下文 + 原生堆），不是应用代码。**
不换推理栈就压不下去 —— 所以"常驻 RSS < 200MB"在当前技术选型下**做不到**，这是已知取舍：

> 响应优先，空闲尽力最低。

```
└─ 五、作者信息
```

- **参数不从界面暴露**：触发阈值、冷静期、滑动幅度、方向角…全部内置在 `Prefs.kt`，改需重新编译。
- **「请滑动」提示没有开关**：姿势锁定后必定出现（约 0.9 秒自动消失）。

## 🔨 构建

```powershell
# 正式包（不可调试）
android\tools\build.ps1 -RunTests -Release

# 同一个 keystore、但可调试的测试包（run-as 可用，便于排查）
android\tools\build.ps1 -Release -Debuggable
```

- 编译需要 `android\keystore.properties` 与 `android\keystore\*.jks`（**仓库里没有**，见"签名"一节）
- 脚本会先把源码镜像到 ASCII 路径再编译 —— AGP 与单测 worker 在非 ASCII 工程路径下会出问题
- 护栏：`python -m unittest probe.test_detector_ref`（**29** 个）+ 上面 `-RunTests`（Kotlin **75** 个）

## 🔒 权限与隐私

- 应用**自己只声明 `CAMERA`**。APK 里另有 `INTERNET` / `ACCESS_NETWORK_STATE`，来自
  MediaPipe 传递引入的 Google Datatransport —— **本应用不用它做任何业务上报**，
  已评估过移除它的风险后决定保留，详见 [NOTICE](NOTICE)。
- 相机画面**只在本机实时处理：不保存、不上传**。
- 悬浮窗使用 `TYPE_ACCESSIBILITY_OVERLAY`，因此**不需要** `SYSTEM_ALERT_WINDOW`。

## ✍️ 签名与自检

发布包用项目自己的 keystore 签名，并在运行时做**签名自检**：
签名与内置白名单不符时，**禁用隔空手势功能**（App 仍可打开，状态区会写明原因）。

诚实说明：它能挡"改包后重签"，**挡不住会反编译的人**（把那几行校验 patch 掉即可）——
它的定位是提高门槛，不是 DRM。

> keystore 与口令**不在本仓库里**（`.gitignore` 已排除）。
> 因此任何拿到源码的人**都无法冒充你发布更新**。
